# 本机实测

v0.2.0 新增的短音频、MP4 与网页导入记录见 [网页与本地样本](2026-09-09-web-local.md)。以下保留 v0.1.0 的课程基线。

记录日期：2026-09-09。Windows 10 x64、Ryzen 7 5800H（16 逻辑线程）、RTX 3050 Laptop 4 GB、NVIDIA 驱动 526.56。Python 3.12.7、PyTorch 2.4.1+cu118、Whisper 20250625、NumPy 1.26.4。

输入为指定课程第一 P《课程目标》，音轨 356.608 秒。所有实测只处理该 P，没有提交整套 69 P 课程。

| 路径 | 音频时长 | 模型/设备 | 处理时间 | RAM 峰值 | GPU 分配峰值 |
| --- | ---: | --- | ---: | ---: | ---: |
| 独立 worker，4 线程 | 356.608 s | small / CUDA | 66.078 s | 3113.0 MiB | 1403.2 MiB |
| Rust 应用完整导入，8 线程 | 356.608 s | small / CUDA | 60.484 s | 2929.9 MiB | 1403.2 MiB |
| 独立 worker CPU 小样本，4 线程 | 20 s | small / CPU | 18.203 s | 1569.1 MiB | 0 |

表中时间来自 worker，不包含源信息读取和网络下载。完整应用路径读取到“字幕需要登录”，因此只下载 8,517,667 字节音轨并转写，没有下载视频画面。模型 small.pt SHA256：`9ecf779972d90ba49c06d968637d720dd632c55bbf19d441fb42bf17a411e794`。

完整 worker 首次运行产生 158 个片段、1481 个字符；再次运行复用两个检查点，墙钟 9.125 秒，片段内容和 ID 完全相同。GPU 数值是 PyTorch allocator 峰值（reserved 1614 MiB），不等于 nvidia-smi 的整卡用量。

另外做了实际强制终止实验：70 秒样本按 30 秒分块，在第一块完成后杀死 Python，重启只复用第一块，完成后共 26 片段、0 重复。第一块检查点字节完全未改；再次重放三个检查点，结果相同。恢复墙钟 20.922 秒，完整重放墙钟 6.672 秒。

运行脚本：`scripts/benchmark-worker.py` 和 `scripts/verify-recovery.py`。输出保存在 `.local-data/benchmarks/`，不提交课程音频、转写原文或个人绝对路径。

**测量局限**：均为单台机器上的单次样本，CPU/GPU 使用的音频长度不同，不能用表直接比较吞吐。旧工具此前“74 秒”仅为历史记录；没有严格同条件对照。没有人工参考稿，CER、专业术语质量、长课稳定性、噪声与混合语言质量尚未量化。8 GB/24 GB GPU 只做策略模拟，不标记为实测。
