# 性能与质量核对（v0.6.0）

默认仍使用原有 OpenAI Whisper。新增 faster-whisper 是可选路径；速度和显存
变化有本机实测，但目前没有人工审核的逐字参考稿，不能据此认定识别更准确。

## 按区间核对

打开课程的“核对”页。重叠的疑点合并展示，展开后仍能看到每条证据及人工
结论；“检查依据待补全”单独计数。没有待办不代表逐字正确。

有本地音频时，可循环回听疑点前后文、调整播放速度；查看二次识别候选时，
播放按钮使用候选自己的区间。切换候选或版本会清除旧循环。

批量复核先预览区间和总时长，再开始识别。系统扩展到完整文字片段边界并
合并重叠区间，最多 5 段、单段 120 秒、合计 300 秒；超出预算会说明原因。
这不是耗时承诺，实际等待取决于设备、模型和加载开销。任务逐段保存完整候选，
取消或中途失败后已保存的候选仍可比较，未完成的一段需重新识别。

比较面板显示原文与候选差异。候选默认不勾选；回听后勾选要采纳的结果，
一次生成一个新文字版本。旧版、旧笔记与引用继续保留，相关旧疑点标记为
已修订；新版需要重新核对。没有文字或依据已变化的候选不能静默替换原文。

语音检测结果按完整音频摘要与检测器身份复用。只修改文字不必重新推理同一
音频，但不会继承旧版的人工确认。更换音频或检测器后会重新检测。

## 选择识别引擎

在“设置”的高级识别配置选择引擎，保存后重新检测环境并进行小样本验证。
faster-whisper 使用独立 Python 和模型根目录；例如本机已准备：

- Python：`D:\CourseWorkbenchRuntime\faster-whisper-cu11\Scripts\python.exe`
- 模型根目录：`D:\CourseWorkbenchRuntime\models\faster-whisper`
- 模型：`small`，已下载在根目录的 `small` 子目录。

本机 RTX 3050 4GB 验证了 CUDA float16、int8_float16；CPU 另测 int8。
模型文件格式不同，不能把原 Whisper 的 `.pt` 目录直接作为新引擎模型目录。
转写不会偷偷下载缺失模型，应先在设置中显式下载。当前适配器不提供 turbo
映射。beam 可手动调整，但更高 beam 并不保证更准确，会改变耗时和输出。

本机独立环境为 Python 3.11.15、faster-whisper 1.0.3、CTranslate2 3.24.0、
NumPy 1.26.4、cuDNN 8.9.7（CUDA 11）。这是适应当前 526.56 驱动的历史兼容
组合，安装时通过 `workers/asr/constraints-cu11.txt` 显式覆盖 CT2 依赖；
不是所有设备的通用安装锁。更高版本驱动应按官方兼容说明另建环境并实测，
不要覆盖原来的 bili2text Python。当前环境另装 requests 与 setuptools<81，
以满足旧引擎的导入要求。GPU DLL 仅由该子进程读取其 Python 根目录的 `cuda`。

官方依据：[faster-whisper](https://github.com/SYSTRAN/faster-whisper)、
[CTranslate2 计算类型](https://opennmt.net/CTranslate2/quantization.html)。

## 完整性与质量的界限

每次转写保存分块 manifest、音频/模型摘要、运行时版本、实际解码配置、阶段
计时与已完成块。全段任务和局部复核都必须通过分块完成性检查；文字、任务状态
和必要来源证据一起提交数据库，避免“已完成但依据没保存”的状态。

时间覆盖和分块完成只能证明处理范围，不能证明每句话没有错字或漏字。
faster-whisper 的诊断分数没有沿用原引擎的未校准阈值；界面会提示依据限制。
人工校对仍是术语、同音词、短漏字的最终核对方式。

`benchmarks/quality/evaluate.py` 支持逐字 CER、术语数量差异和时间区间指标，
但只有音频摘要匹配且明确经过人工审核的参考稿才能产生质量结论。
不传参考稿只记录性能；未审核稿会被拒绝。详见
[参考稿说明](../benchmarks/quality/README.md)。

语音边界分块仅作为 worker 实验接口，未接入默认配置。它保留全部时间轴，
在边界存在语音对齐歧义时拒绝结果，而不是猜测删字或合并。固定五分钟恢复块
仍是生产默认。模型跨请求常驻暂未引入，进程结束即释放模型。

实测数据和限制见 [性能记录](../benchmarks/2026-10-04-performance-quality.md)，
验收见 [v0.6.0 验证记录](validation-performance-quality-0.6.0.md)。
