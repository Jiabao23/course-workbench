# 资源自适应策略

流程：检测能力 → 推荐候选 → 实际小样本验证 → 手动覆盖。检测 CPU/内存/磁盘、NVIDIA GPU/驱动/空闲显存，并在用户选择的 Python 中探测真实的 Torch/CUDA/Whisper 可用性。

| 能力 | 初始候选方向 | 说明 |
| --- | --- | --- |
| CPU / GPU 后端不可用 | tiny/base | 控制线程，保持单任务 |
| 约 4 GB GPU | base/small | 给系统和模型加载保留空闲显存 |
| 约 8 GB GPU | small/medium/turbo | 仍由空闲显存和实际试跑决定 |
| 12–24 GB 及以上 | 更大模型候选 | 不自动增加并发或安装本地 LLM |

省资源、均衡、高质量是候选偏好；高级设置可指定模型、设备和线程。GPU 并发首版固定 1。使用设置中的样本验证处理已有音轨前 60 秒，记录模型、设备、线程、速度、RAM、PyTorch 分配/保留显存峰值与环境指纹。

**显存峰值是 PyTorch 分配器测量，不是整张显卡的系统总占用。** 环境指纹不同的记录不用于自动降级依据。OOM 时保留检查点；只切换到已有成功实测的较小模型或 CPU 配置，换模型重新形成独立版本；没有已验证候选时提示手动调整并重试。

CPU 和 NVIDIA CUDA 在本机跑过；8 GB、24 GB、驱动不兼容等政策分支只做模拟测试。AMD/Intel/Apple GPU 不标成支持后端，提供 CPU 路径。PyTorch/CUDA 的安装组合应跟随驱动能力，不能将某台机器的 2.4.1+cu118 固定给其他用户。

质量目标需独立评估：为长课、中英混合、专业术语和噪声建立人工核对稿，计算中文 CER、术语召回/误写率、时间轴偏移。当前只有速度和资源基线，没有充分证据宣布某个模型的中文质量更好。
