# 通用视频链接与本地文件导入

本轮由用户要求新增非 B 站视频网站，并完善本地上传和额外测试。这里的上传指把用户选择的文件导入本机资料库。既有 B 站、版本、笔记和资源策略保持兼容。

## 方案

复用已接入的 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 解析公开视频页面和 HTTP(S) 音视频直链，在 Rust 中新增独立 `WebProvider`。不逐一重写网站爬虫，也不要求用户在外部下载器与工作台之间搬运数据。原 B 站适配器继续负责分 P 和细分字幕状态。

导入对话框分为“B 站链接”“其他视频网站”“本地文件”。本地入口支持原生文件选择、拖入一个文件及粘贴绝对路径，显示文件名、时长、类型和处理范围；多文件拖入明确提示逐个导入，不静默丢弃文件。

## 行为与边界

- 通用来源先用结构化 JSON 读取单个视频信息，拒绝纯播放列表、直播、尚未开始的视频和不可读取的受保护来源。
- 优先读取 SRT/VTT 字幕，区分人工和自动字幕，按设置语言优先选择。字幕处理使用 `--skip-download`，由 yt-dlp 处理网站请求和按域 Cookie，不加载 Whisper。
- 无字幕时优先独立音轨；若来源只有音视频混合文件，预览明确提示需要下载原媒体再提取音频。不会把这条路径描述成“只下载音轨”。
- 沿用仅字幕、字幕优先、重新转写三种处理方式。解析失败、登录要求、缺工具和请求超时提供明确原因；失败不能被当作无字幕。
- 支持范围以当前 yt-dlp 版本和来源实际状态为准，不承诺任意网站可用。自动发现本机可用的 Node.js 供需要 JavaScript 的解析器使用，未安装时不影响其他网站和本地文件。
- 新来源使用 `sourceKind=webMedia`，不更改 SQLite schema。原网页保存在资产和 Markdown 来源中；播放器、原网页跳转和引用适配新来源。
- 所有新进程沿用超时、取消和 Windows 进程树管理。预览子进程登记到应用退出控制；读取元数据不下载媒体。

## 验证

纯测试覆盖 URL 分流、元数据/字幕选择、播放列表和直播拒绝、仅字幕命令、来源时间链接、本地拖入校验。真实测试分开记录：本机回环网页夹具验证字幕优先与音轨回退；至少一个实际非 B 站来源验证公开链接；本地中文音频和视频经原生桌面进入转写、回听及导出。网站限制和网络失败原样记录。
