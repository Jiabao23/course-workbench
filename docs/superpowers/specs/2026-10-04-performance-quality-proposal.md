# 算法、性能与质量优化建议

日期：2026-10-04。状态：已获用户授权执行。以下为实施前设计；实际范围与证据见 [v0.6.0 验证记录](../../validation-performance-quality-0.6.0.md)。
基线：v0.5.0，398475e；个人本地应用，RTX 3050 4GB 为首个实测设备。

## 目标和已知事实

在保持版本、引用和恢复语义的前提下，降低等待时间和人工核对成本，并用
人工参考稿证明质量变化。性能优化和识别质量分别验收，不能用速度代替准确率。

代码核查：worker 按 300 秒划分恢复块，每个独立请求重新校验/加载模型；
一个请求内部已复用模型，不应重复声称整段课程逐块加载。Whisper 调用固定
condition_on_previous_text=True。质量模块对每个语音区间从头遍历文字段，
诊断关联也使用重复线性查找。语音证据目前按文字版本保存，核对时重新计算
音频内容摘要。以上是优化候选，尚未做阶段耗时剖析证明谁占主导。

现有测试验证功能闭环，但没有人工逐字参考稿，也未量化漏转召回/误报。
此前本机约 357 秒课程的 worker 单次耗时不能直接作为不同引擎的公平对照。

## 路线比较

| 路线 | 内容 | 成本与取舍 |
| --- | --- | --- |
| A：先优化现有流程（推荐起点） | 阶段计时、区间算法、证据复用、重复疑点合并、局部对照 | 模型输出可保持不变；较易验证收益，不能单独解决识别错字 |
| B：新增可选推理引擎 | faster-whisper/CTranslate2，同模型 FP16/INT8 对照 | 有速度/显存优化空间；增加模型格式与运行时适配，输出未必完全相同 |
| C：重点提升困难片段 | 语音边界分块、受限上下文、术语提示、选择性二次识别 | 可能降低错误和核对成本；需要参考集，可能增加耗时或引入新错误 |

建议按 A → B 小范围实验 → C 有依据地启用推进。每次只改变一项策略，
通过后组合验证，保留可回退的已验证配置。

## 设计

### 1. 线性区间核对与按身份复用

- 先排序并合并文字覆盖区间，再用双指针计算语音区间减去文字覆盖。
  排序后扫描目标为 O(S+V)，替换当前最坏 O(S×V) 的重复遍历。
- 片段 ID 到诊断记录预建索引，避免双向逐项查找；保留重复 ID 校验。
- 用随机生成与边界样本对照旧算法，要求区间结果一致；用长课程级数据
  测量耗时/内存，不能把理论复杂度直接写成整机加速比。
- VAD 原始证据归音频内容摘要和检测器身份所有；每个文字版本单独计算
  覆盖报告和复核状态。只改文字不必重新推理 VAD，旧人工确认仍不沿用。
- 导入/转换时可顺便计算完整摘要，应用拥有的不可变缓存可复用；外部
  文件变化或身份不确定时重新哈希，不能仅凭同路径/大小认定相同音频。
- UI 将重叠缺漏提示归为同一核对区间，原始证据和状态分别保留；证据不足
  与具体疑似错漏分开计数，不通过隐藏问题来改善待办数。

### 2. 按语音边界规划分块

- 将恢复检查点范围与模型实际解码窗口分开。保留恢复块上限，在目标边界
  附近优先选择可靠停顿；没有停顿时仍有有界切分路径。
- 给解码输入保留少量前后上下文，初始可试 1–2 秒重叠；只有核心区间
  归该块输出。重叠只用于理解和对齐，不重复写入文字。
- 拼接综合时间范围和文本对齐；不得仅凭相同词句删除教师真实重复的话。
  歧义边界保留候选并提示复核。
- 保存版本化分块 manifest：原音频起止、核心区间、上下文、规划器版本。
  完整性验证按 manifest 核对提交范围，不能继续假设块数恒为 ceil(时长/300)。
- VAD 首先用于选边界，默认保留全部原音频。跳过静音另做对照实验；
  被同一个 VAD 漏检的讲话不能又被其自我验证为“没有漏转”。
- 测试长连续讲话、低音量、停顿中短词、块边界术语、真实重复、尾部不足
  一秒、取消恢复及时间映射。

### 3. 量化推理与资源策略

- 在 AsrEngine 接口下增加 faster-whisper 可选适配器，现有引擎保留。
  首轮比较同一 multilingual small 模型的现有路径、FP16 与 int8_float16；
  CPU 另测 INT8。支持的计算类型由运行时查询和实际试跑决定。
- RTX 3050 4GB 起步并发 1、batch 1。更强设备先小样本试跑，再逐步增加
  batch；多课程并发和单模型 batch 是不同配置，分别验证。
- 新引擎使用独立环境与独立模型目录。当前上游说明 GPU 依赖涉及 CUDA 12 /
  cuDNN 9；本机历史 Torch cu118 组合不能直接假定兼容，实施时先检查当前
  驱动、可用运行时和锁定版本，不升级或覆盖 bili2text 环境。
- 统一语言、提示、beam、音频预处理、实际输出收集方式与线程；报告首次
  加载和复用加载耗时。上游加速数据不是本机预期值。
- 新引擎显存统计不能继续借用 PyTorch allocator；同时记录进程 RAM、
  可获取的进程/整卡显存指标及测量口径，避免拿不同口径比较。

### 4. 按疑点分配第二轮识别预算

- 结合未覆盖讲话、块边界、重复、诊断与术语冲突生成可解释的优先级，
  用标注集调节阈值，不显示未经校准的“正确率”。不同引擎分数不直接混用。
- 先提供一键批量生成疑点候选，明确显示总音频长度与预计成本；限制总预算，
  重叠区间合并，每段最多重试一次，避免无限循环。
- 二次识别应有明确差异：增加边界上下文、调整解码/上下文继承策略或使用
  已验证的另一个配置。相同输入相同设置重复运行不能被当作独立验证。
- 术语表由课程相关词或用户确认的修正组成，只作为有限提示和对照建议；
  不全局替换同音词。只有基准证明受益才默认启用。
- 原文、候选差异和音频循环回听放在同一核对面板。采纳仍显式创建版本；
  保存全部引擎/模型/量化/解码/区间参数及父版本。

### 5. 降低连续复核的模型加载开销

- 先测首次加载、推理、转换、哈希各自耗时；若加载主导连续短复核，再增加
  单模型 worker 会话复用。
- 4GB 设备只保留一个模型，提供空闲释放和压力释放；切模型先释放旧模型。
  初始化、取消、进程崩溃后重建都由 Rust 管理。
- 未结束的任务不得共享可变识别状态。扩展 request ID、会话状态、超时和
  内存指标；切课程清理提示上下文，不能把上一课程文字带入下一课程。
- CPU 分析与 GPU 转写重叠执行属于后续实验，必须有有界队列和取消传播；
  不直接移除现有资源排他保护。

## 验证与默认配置准入

建立小而明确的开发集和保留验证集：课程目标全段人工校准，再加入术语、
中英混合、噪声/低音量、静音及长课边界样本。人工参考不能直接使用当前
ASR 输出或让同一模型为自己判卷；无法确认的音频单独标注，不强行写答案。

每次对比记录：

- 质量：规范化规则固定的中文 CER、术语错误、漏转召回/误报、边界丢字与重复；
  同时保存未经繁简/标点归一化的原始差异。小样本结论不外推所有课程。
- 性能：端到端/纯推理时间、RTF、首次/热启动、RAM/显存峰值、取消延迟；
  短样本多次取中位数，后台负载和冷/热缓存状态随记录保存。
- 体验：同一组疑点完成核对所需时间、点击数、误采纳及漏处理数量。
- 可靠性：中断/恢复、OOM、依赖缺失、manifest/模型/文件变化、跨引擎缓存
  隔离、新版本旧引用以及候选陈旧拒绝。

“均衡”仅选择质量和可靠性满足约定界限的较快配置；“高质量”需在保留集
有可重复改善才推荐；“省资源”明示性能/质量取舍。速度和质量没有同时
改善时，展示可比较的选择，不把某一个总分隐藏的取舍强推给用户。

## 分阶段交付及文件方向

第一批：测量与参考基准、区间算法、疑点合并、差异高亮和循环回听。
第二批：独立 faster-whisper 适配、同条件模型/量化对照、能力试跑。
第三批：语音边界分块 manifest、选择性复核；模型常驻依据剖析结果决定。
上一轮建议中的草稿恢复、备份和 Obsidian 同步状态继续保留为独立产品任务。

实施前拟定位置（实际规划器在 Python worker 中，与实际解码/检查点共同校验）：

- `benchmarks/quality/`：样本清单、参考标注规范、CER/术语和检测指标脚本。
- `benchmarks/experiments/`：固定配置、实验清单、资源与质量结果。
- `workers/asr/engines/`：保持 JSONL 边界的引擎适配与能力查询。
- `crates/core/src/audio_plan.rs`：确定性边界/manifest/拼接策略。
- `crates/core/src/quality_intervals.rs`：区间差集与展示分组。
- `contracts/`：扩展引擎身份、manifest、候选来源和会话协议。
